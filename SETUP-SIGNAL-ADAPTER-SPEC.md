# Core Setup -> Signal -> Domino Adapter Spec

Date: 2026-08-19

## Purpose

Bridge the current deterministic Strat setup detector into the normalized actionable-signal, lifecycle, and multi-timeframe domino layers without duplicating setup logic.

Production path:

`CORE SETUP -> NORMALIZED SIGNAL -> SIGNAL LIFECYCLE -> DOMINO / CARRIER STATE`

## Rules

1. Core setup direction and trigger are authoritative inputs.
2. Setup-defined magnitude is preserved exactly when present.
3. No Level of Reclaim is inferred. Unknown reclaim remains `null` until source-verified per setup.
4. Signal start/end timestamps are supplied by the data/session layer; the adapter does not invent bar boundaries.
5. Unsupported/no-magnitude setups may use a borrowed higher-timeframe objective only when explicitly supplied.
6. Non-directional, pending, or ambiguous setup objects do not become actionable signal objects.
7. Lifecycle state, not mere setup existence, determines whether a timeframe is an active domino carrier.
8. Each timeframe retains its own setup and lifecycle state. A lower timeframe does not automatically activate a higher timeframe.
9. Mixed bullish/bearish timeframe states are preserved rather than forced into alignment.

## Validation harness

- `tests/setup-signal-adapter-validation.js`

The harness includes a setup generated by `core-engine-v0.3.js` plus multi-timeframe core-style setup objects. It checks trigger/magnitude preservation, no invented reclaim, lifecycle activation/expiration, multiple active carriers, higher-timeframe non-activation when its trigger is not crossed, mixed-direction preservation, and ignoring non-directional setups.

Execution status is reported separately in `VALIDATION.md`; presence of the harness does not by itself prove a PASS run.
