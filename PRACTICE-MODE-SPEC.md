# Practice Mode — v0.1

Date: 2026-08-20

## Purpose

Practice Mode is a deterministic paper-trading layer for learning execution and measuring setup behavior without risking capital.

It is intentionally separate from setup validity. A Strat setup may exist without a practice trade, and a practice trade may use different management rules without changing the underlying setup classification.

## Initial flow

`WATCHLIST -> LIVE/REPLAY SETUP -> PRACTICE TRADE ARMED -> ENTRY TRIGGER -> OPEN -> TARGET / STOP / AMBIGUOUS -> RESULT LOG`

## v0.1 scope

Implemented in `practice-trade-engine.js`:

- BULL / BEAR direction;
- setup label provenance;
- exact trigger price;
- structural stop price;
- first target / magnitude price;
- quantity;
- ARMED -> OPEN -> TARGET_HIT / STOPPED / AMBIGUOUS lifecycle;
- strict trigger rule: equality alone does not count as in-force;
- MFE and MAE tracking;
- result normalized to R;
- event log;
- coarse-OHLC ambiguity preservation.

## Critical ambiguity safeguard

Historical or live bars may show that the trigger, stop and/or target were all crossed during the same candle while not revealing the intrabar order.

Practice Mode must not fabricate the path.

Examples:

- a bullish entry trigger and target both lie inside one 15-minute bar;
- a later bar spans both stop and target;
- a 3/outside bar crosses multiple execution levels.

Those cases become `AMBIGUOUS` unless a lower-timeframe/tick sequence can establish the order.

This follows the existing project rule that completed OHLC cannot establish path direction when both extremes were traversed.

## Trigger semantics

For BULL:

`bar.high > triggerPrice`

For BEAR:

`bar.low < triggerPrice`

Equality is not enough. This mirrors the existing in-force convention.

## Stop geometry

v0.1 does not invent stop placement. The caller must supply a stop generated by an explicit practice rule, such as:

- setup structural invalidation;
- inside-bar opposite side;
- prior bar extreme;
- later ATR/trailing variant;
- lower-timeframe reversal/reclaim rule.

The engine only validates that the stop/trigger/target geometry is coherent.

## Experiment architecture

The research engine should hold the market setup constant while comparing execution variants.

Examples:

`2-1-2U setup`

Entry variants:
- exact trigger;
- close confirmation;
- first pullback after trigger;
- lower-timeframe confirmation;
- FTFC/sector-confirmed trigger.

Management variants:
- no trail;
- fixed-percent trail;
- ATR trail;
- prior-bar trail;
- lower-timeframe Strat reversal trail;
- tighten after first magnitude;
- partial at magnitude + runner.

Exit variants:
- target/magnitude;
- opposing reversal;
- reclaim failure;
- trailing stop;
- time exhaustion;
- end-of-session.

Performance comparison must include sample size and out-of-sample validation. Highest historical win rate alone is not sufficient.

## Intended UI

Practice Mode should eventually surface a compact sequence:

`WHAT IS SETTING UP -> ENTRY RULE -> ARMED -> IN TRADE -> MANAGEMENT -> RESULT`

It should be usable on a small cross-sector watchlist while a broader universe is scanned more slowly for research and candidate rotation.

## Non-goals in v0.1

- no live broker execution;
- no automatic order placement;
- no options position model yet;
- no trailing-stop optimizer yet;
- no AI-generated entry/exit authority;
- no assumption that a backtested winner is a valid live edge.

## Validation

Focused harness:

`tests/practice-trade-engine-validation.js`

The harness covers strict trigger semantics, bull/bear results, MFE/MAE, stop/target outcomes, invalid geometry, terminal immutability and coarse-bar ambiguity.
